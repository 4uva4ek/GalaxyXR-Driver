## What this repo is

SteamVR driver for the Samsung Galaxy XR over Steam Link (vrlink), fork of sboys3/CustomHeadsetOpenVR.
Ships as the `GalaxyXRNative` vendor driver and coexists with the original `CustomHeadsetOpenVR` driver. GPLv2.

| Part | Tech | Where |
|---|---|---|
| SteamVR driver — pose/Kalman, image processing, distortion, identity | C++17 | `CustomHeadsetOpenVR/` |
| GUI — settings, install/switch, diagnostics | Vite + TypeScript + Lit + Fluent UI v3 + Tauri 2 (Rust) | `CustomHeadsetGUI/` (`src-lit/` tree) |
| Camera calibration + distortion tuner scripts | Python 3.9+ | `tools/` |
| User docs | Markdown | `Docs/` (`StreamFrame.md`, `TunerUsage.md`) |
| Vendored libs — **read-only, never edit** | various | `ThirdParty/` (openvr, minhook, nvenc, zlib, json, easywsclient) |

Runtime contract: GUI and driver exchange JSON under `%APPDATA%/GalaxyXR/CustomHeadset/` —
`settings.json` (GUI writes, driver hot-reloads), `info.json` (driver → GUI), `gui-settings.json` (GUI only),
distortion profiles in the `Distortion/` subfolder (referenced by name).

## Change routing — which files to edit for what

### New or changed user setting (full chain — every step is required)
1. `CustomHeadsetOpenVR/src/Config/Config.h` — struct field + C++ default
2. `CustomHeadsetOpenVR/src/Config/ConfigLoader.cpp` — parse + default write (+ migration if semantics change)
3. `CustomHeadsetGUI/src-lit/domain/types.ts` — TS type (mirror the C++ struct)
4. `CustomHeadsetGUI/src-lit/domain/driver-defaults.ts` — TS default (**must equal the C++ default**)
5. `CustomHeadsetGUI/src-lit/features/<page>.ts` — bind the control; pages are thin views over the shared `GalaxySettingsBase` in `src-lit/state/galaxy-settings.ts`; add `app-field-tip` text + reset button where the pattern uses them
6. Driver consumption site, if the value does anything (`DeviceProvider.cpp`, `FrameProcessor.cpp`, `Headsets/GalaxyXR.cpp`, `src/Distortion/`)
7. New user-visible strings via `t(...)` (source catalog: `CustomHeadsetGUI/src/locale/messages.xlf`)
8. Test: vitest under `CustomHeadsetGUI/src-lit/**/*.test.ts` (`npm test`), or `tools/Test-GuiReadiness.cjs`; pure logic gets a C++ test in `CustomHeadsetOpenVR/tests/`
9. Docs: `Docs/StreamFrame.md` / `Docs/TunerUsage.md` / README "Recommended settings" when user-visible

If the value only applies after a SteamVR restart (identity, render resolution, input profile, stream quality), say so in the field tip: **"Requires a SteamVR restart."**

### Build, version, tests
- **Build gate (mandatory)**: on every cavecrew invocation and before reporting any completed change, run the full local build from the repo root: `powershell -NoProfile -ExecutionPolicy Bypass -File tools/Build-Portable.ps1` (driver + GUI; auto-stages a fresh `output/CustomHeadset-Test-<timestamp>`, never deploys; works on Windows PowerShell 5.1 and 7). It must exit 0 with `Built test package: ...`; on failure fix the root cause and re-run. Never report done on a red build, and never silently downgrade to `-DriverOnly`/`-GuiOnly`.
- Full build + release staging: `node build.js [--vendor galaxyxr|neutral] [--no-driver] [--no-gui]` → `output/CustomHeadset-STAGING-<ver>[-Galaxyxr]-Windows/`
- Version bump (touches 4 files — **never hand-edit the version**): `node bump-version.js x.y.z[-tag]` → `tauri.conf.json`, `Cargo.toml`, `Config.cpp`, `driver.vrdrivermanifest`
- GUI unit tests: `cd CustomHeadsetGUI && npm test` (vitest; e.g. `src-lit/state/galaxy-settings.test.ts`, `src-lit/domain/*.test.ts`)
- C++ tests are standalone `main()` programs (no framework): compile the test + the sources it includes + `-I ThirdParty/json/include`, C++17, then run. E.g. `tests/SteamVRSettingsJournalTest.cpp` + `src/Config/SteamVRSettingsJournal.cpp`
- Tool tests: `node tools/Test-GuiReadiness.cjs`, `node tools/Test-SteamVRSettingsDiff.cjs`, `powershell -File tools/Test-SteamVRSettingsJournal.ps1`, `powershell -File tools/Test-VrlinkCapabilities.ps1`
- Linux driver (CMake): `cmake .. && make` → `bin/linux64/driver_CustomHeadsetOpenVR.so`

## Invariants — do not break
1. **Vendor dual-build**: with `VENDOR_GALAXYXR` the driver is `GalaxyXRNative`; without it `CustomHeadsetOpenVR` (neutral). Both must keep building and coexist. Never hardcode one name where the define decides.
2. **Legacy headsets**: MeganeX 8K / Dream Air support is upstream and still shipped — `meganeX8K` / `dreamAir` config sections and the Driver Settings tab must keep working.
3. **Schema migrations**: changing the meaning of an existing key requires a versioned migration in **both** `ConfigLoader.cpp` and `CustomHeadsetGUI/src-lit/state/galaxy-settings.ts` (pattern: `streamFrameSchema` bump). Migrations auto-upgrade exact old defaults only — never rewrite user tuning.
4. **SteamVR `settings.vrjson` writes** go through the journal (`SteamVRSettingsJournal.*` + `driver_installation.rs`) so uninstall restores them.
5. `ThirdParty/` is vendored — never modify.
6. GPLv2: new code and dependencies must stay GPLv2-compatible.
7. New user-visible strings go through the XLIFF source catalog (`CustomHeadsetGUI/src/locale/messages.xlf`) + `t(...)` in the GUI; don't hand-edit the existing `zh-Hant` / `ja` translations unless asked.
8. Tuning changes keep the repo's dated-campaign comment convention (e.g. `// schema-2 migration (2026-08-15) ...`) — explain *why* with a date.
